# 上下文预算（L2 参考文档 · 触发条件：会话变慢/质量下降，或新增 skills/agents/MCP/rules 组件前）

> 本文件为按需读取的参考文档（无触发不读）。
> 源：ECC skills/context-budget。与本技能 L0/L1/L2 渐进披露哲学同源：token 就是注意力，省下的就是准确率。

## 预算红线（超线即瘦身）

| 组件 | 阈值 | 超线动作 |
|------|------|----------|
| 单个 agent 定义 | >200 行 | 拆分或瘦身 |
| 单个 SKILL.md | >400 行 | 细节移入 L2 按需文档 |
| 单个 rules 文档 | >100 行 | 按触发条件拆分 |
| MCP 服务器总数 | >10 | 砍掉低频或可被 CLI 替代的 |
| 单个 MCP 工具数 | >20 | 精简（每工具 ≈500 token schema 开销） |
| 全局工具总数 | >80 | 同上 |
| CLAUDE.md 全链 | >300 行 | 细则下放 docs/rules/ |

## 三桶分类法

每次新增组件后过一遍：

- **常驻**：CLAUDE.md 引用、活跃命令依赖 → 保留
- **偶发**：领域相关、有明确触发条件 → 按需加载（本技能的 L2 模式）
- **冗余**：无引用、内容重叠、场景不符 → 删除或惰性加载

## 常见膨胀源

- agent/skill 的 description 超长（每次派发都会载入）
- 内容重复的组件（skill 复制 agent 逻辑、rules 重复 CLAUDE.md）
- 包装简单 CLI 的 MCP server（gh/git/npm 本身直接可用）
- skill 自身携带的过期备份文件随项目拷贝扩散
