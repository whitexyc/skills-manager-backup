# 项目适配登记（L2 参考文档 · 触发条件：项目 onboarding 盘点 / Reviewer 发现铁律与项目现状冲突时）

> 本文件为按需读取的参考文档（无触发不读）。
> 背景：铁律与项目现实脱节时（如铁律 7 要求响应含 timestamp/request_id，而既有项目全库未实现），每个 Reviewer 都要重新裁决一次——登记制让裁决只发生一次。

## 流程（onboarding 必做一次，此后按需维护）

1. Planner 对照 `CLAUDE.md §0` 逐条盘点：本项目的技术栈与既有代码能否满足每条铁律
2. 不能满足的条目登记到下表：**状态 = 豁免**（永久偏离，写明理由）**/ 待补**（列入 backlog，排期补齐）
3. Reviewer 审查时以本表为准：已登记条目按登记状态执行，不再重复裁决；未登记的新冲突照常驳回，并建议 Planner 登记入库
4. 「待补」条目补齐后更新状态为「已补齐」并注明补齐模块号
