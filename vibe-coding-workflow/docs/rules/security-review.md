# 深度安全审查清单（L2 参考文档 · 触发条件：涉及认证/授权/用户输入/密钥/API 端点/支付时）

> 本文件为按需读取的参考文档（无触发不读）。
> 源：ECC skills/security-review。
> 与 audit-scan.js 的分工：audit-scan 管"确定性可扫的"（密钥正则/危险命令/注入模式，铁律 9 机械兜底）；本清单管"需要理解的"（鉴权逻辑、数据暴露面、信任边界），在 Review 阶段人工/AI 逐项过。

## 触发场景

新增认证/授权逻辑、处理用户输入或文件上传、新建 API 端点、接触密钥凭据、支付或敏感数据存储传输、集成第三方 API。

## 审查清单

### 1. 密钥管理
- [ ] 零硬编码密钥/token/密码（铁律 9 + audit-scan 机械兜底）
- [ ] 密钥全部走环境变量或密管服务；启动时校验必需密钥存在并快速失败
- [ ] `.env*` 在 .gitignore；git 历史无泄漏

### 2. 输入验证
- [ ] 所有用户输入经 schema 校验（zod/pydantic/Bean Validation）后才进业务层
- [ ] 文件上传：类型白名单 + 大小上限 + 存储路径不受用户输入控制（防路径穿越）
- [ ] 注入面：SQL 参数化（铁律 9）、命令行参数化、模板输出转义

### 3. 认证与授权
- [ ] 认证失败统一文案（不泄露"用户不存在 vs 密码错误"的区别）
- [ ] 每个 API 端点显式声明鉴权要求，默认拒绝
- [ ] 会话/token 有过期与撤销机制；敏感操作二次确认

### 4. 数据暴露
- [ ] API 响应不返回多余字段（密码哈希/内部 ID/堆栈）
- [ ] 错误响应走统一格式（铁律 7），不回显内部细节
- [ ] 日志不打敏感信息（铁律 8）

### 5. 依赖与传输
- [ ] 新依赖引入前查已知漏洞（npm audit / pip-audit）
- [ ] 外部传输走 TLS；服务间通信不明文传敏感数据
