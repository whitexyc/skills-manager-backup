# 接口规范（统一返回格式）（L2 参考文档 · 触发条件：编写 Controller / API）

> 本文件为按需读取的参考文档（无触发不读）。铁律提炼见 `CLAUDE.md §0` 第 7 条。
> 源：原 CLAUDE.md §5。

## 1. 统一响应结构

所有 API 接口必须遵循统一返回格式：

```json
{
  "code": 0,
  "msg": "success",
  "data": {},
  "timestamp": 1690000000000,
  "request_id": "uuid-v4"
}
```

## 2. 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | `int` | 是 | 状态码：`0` 表示成功，非 `0` 表示失败 |
| `msg` | `string` | 是 | 状态描述信息 |
| `data` | `object / array / null` | 否 | 响应数据，成功时返回 |
| `timestamp` | `long` | 是 | 服务器时间戳（毫秒） |
| `request_id` | `string` | 是 | 请求追踪 ID，用于日志关联 |

## 3. 状态码规范

| code | 含义 | 说明 |
|------|------|------|
| `0` | 成功 | 请求处理成功 |
| `400` | 参数错误 | 请求参数校验失败 |
| `401` | 未认证 | 用户未登录或 Token 过期 |
| `403` | 无权限 | 用户无此操作权限 |
| `404` | 资源不存在 | 请求的资源未找到 |
| `409` | 冲突 | 资源状态冲突（如重复创建） |
| `500` | 服务器错误 | 服务端内部异常 |
| `503` | 服务不可用 | 依赖服务不可用（如 AI API 超时） |

> **业务错误码**：HTTP 状态码不够细分时，可在 `data` 中增加 `biz_code` 字段携带业务错误码。建议按模块分段：

| 段位 | 模块 | 示例 |
|------|------|------|
| 1xxx | 用户模块 | `1001`=用户名已存在，`1002`=密码强度不足 |
| 2xxx | 订单模块 | `2001`=库存不足，`2002`=订单状态非法 |
| 3xxx | 支付模块 | `3001`=余额不足，`3002`=重复支付 |
| 9xxx | 通用业务 | `9001`=限流，`9002`=操作过于频繁 |

## 4. 分页响应结构

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "items": [],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 100,
      "total_pages": 5
    }
  },
  "timestamp": 1690000000000,
  "request_id": "uuid-v4"
}
```

## 5. 错误响应结构

```json
{
  "code": 400,
  "msg": "用户名不能为空",
  "data": {
    "field": "user_name",
    "reason": "required_field_missing"
  },
  "timestamp": 1690000000000,
  "request_id": "uuid-v4"
}
```
