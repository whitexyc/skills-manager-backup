# 规则蒸馏维护流程（L2 参考文档 · 触发条件：定期维护铁律时）

> 源：ECC skills/rules-distill；instinct 经验沉淀层源：ECC skills/continuous-learning-v2（只取模型不取 hook 基建：其观察 hook 绑定 Claude Code，且原生 Windows 上后台观察器无效）。

## 目的

让铁律随真实使用**演化**，而不是靠人定期想起来改。数据源 = 闸门驳回记录 + 违规台账 + 经验台账。

## 流程（确定性收集 + LLM 裁决，两阶段）

### Phase 1 收集（确定性脚本）

- **闸门自动收集**：`check-gates.js` / `delivery-gate.js` 每次失败自动追加 `memory/violations.md`（`GATE_MODULE`/`GATE_VIOLATIONS_FILE` 可配，无需手工）
- 收集 `memory/agent-activity-log.md` 中被驳回模块的「违反规则」标注
- 台账：`memory/violations.md`（自动追加，含模块/铁律/日期/原因；轮次与聚合在蒸馏阶段处理）

台账格式：

```
| 模块 | 铁律 | 日期 | 原因 |
|------|------|------|------|
| module-003 | 4（注释缺失） | 2026-08-23 | public 方法无 docstring |

### Phase 1.5 经验沉淀（instinct 层）

violations 记「违反了什么」，instinct 记「学到了什么」——用户纠正、反复走通的流程、踩坑结论，先沉淀为**原子经验**再参与蒸馏。

台账：`memory/instincts.md`（阶段退出时追加）：

```
| 日期 | 触发场景 | 动作 | 置信度 | 证据 | 范围 |
|------|----------|------|--------|------|------|
| 2026-09-06 | 写确定性脚本时 | 先写夹具再写实现 | 0.7 | module-001/004/005 夹具先行均抓到真 bug | global |
```

- **原子性**：一条经验 = 一个触发场景 + 一个动作，不写复合句
- **置信度**：0.3 试探 / 0.5 相关时应用 / 0.7 强（自动执行）/ 0.9 近确定；重复观察且用户未纠正 → 升；用户明确纠正、长期无命中、出现反例 → 降
- **范围**：语言/框架/目录习惯 → project；安全习惯、通用最佳实践、工具流程 → global
- **升全局门槛**：同一经验在 2+ 项目出现且平均置信度 ≥ 0.8

### Phase 2 裁决（LLM 交叉阅读）

- 把台账（violations + instincts）+ 现有铁律全文交给 LLM 交叉阅读
- 判据：
  - 同一原则反复出现（违规重复命中 / instinct 高置信多源一致）→ **升级/加粗**为铁律
  - 铁律长期零命中 → **降级/删除**
  - 误报集中的规则 → **调整验证方式或阈值**（GATE_MAX_*）
  - 置信度 ≥0.7 且与现有规则不冲突的 instinct → 先并入 docs/rules/ 对应文档，暂不成铁律

## 输出

- `CLAUDE.md §0` 铁律表增删改（**必须**同步 `SKILL.md` 铁律区）
- `check-gates.js` / `delivery-gate.js` 阈值或正则调优建议
- `memory/instincts.md` 置信度升降与范围变更

## 频率

- 每完成 5-10 个模块，或每月一次
- 触发入口：Planner 或用户主动发起「铁律蒸馏」
