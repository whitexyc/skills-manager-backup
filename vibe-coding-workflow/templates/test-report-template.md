## 5. 环境性失败归因

> 当测试失败时，先按以下矩阵归因，再决定处理方式。环境性失败不计入阻塞，但必须给出可复现证据（缺依赖报错、mock 缺失、平台差异）与归因说明，并在「验收结论」备注注明；禁止把因环境缺失未收集 / 被跳过的用例记为通过。

| 现象 | 判断标准 | 归类 | 处理方式 |
|------|----------|------|----------|
| 依赖包 / 插件缺失报错（如缺 pytest-asyncio 导致 async 用例未收集） | 重复运行稳定失败；补依赖后重跑即通过 | 环境性失败 | 修复测试基建（补依赖 / 补齐 mock）后重跑，不阻塞、不消耗业务重试次数 |
| mock 缺失 / 依赖服务未启动 | 单独跑该用例失败，基线模块同一测试通过 | 环境性失败 | 补齐 mock / 启动依赖服务后重跑 |
| 平台差异（Windows 长路径、缺编译器） | 其他平台通过，本平台失败 | 环境性失败 | 记录平台差异，缩短路径 / 换 uv / 安装编译器 |
| 代码行为不符合预期 | 环境与基建正常，输出仍与预期不符 | 真实回归 | 走失败回退，反馈 Developer 修复 |
| 无法确定 | 环境与代码均无明显线索 | 待排查 | 记录现场信息，必要时升级处理 |
