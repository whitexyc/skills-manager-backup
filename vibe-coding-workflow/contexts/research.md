# 研究模式上下文（Planner / 需求分析注入）

> 源：ECC contexts/research.md。

模式：研究 / 规划

## 行为
- 先调研后结论；结论附来源
- 需求澄清优先于假设
- 技术选型对比得出结论 → **建议记 ADR**（决策信号，见 docs/rules/adr.md）
- 输出物只有 plan.md + acceptance-criteria.md，**绝不写代码**

## 优先级
1. 范围界定（哪些模块、边界）
2. 验收标准先行（怎么算完成）
3. 技术方案（含风险与依赖）

## 造轮子前先查重（search-first）

> 源：ECC skills/search-first。规划新功能/新依赖/新工具函数前必须先走一遍。

快查顺序：repo 内已有实现 → 包管理器（npm/PyPI）→ MCP → 本地 skills → GitHub 成熟实现。渠道不可用要如实声明，不许静默跳过后报"没找到"。结论落入四选一并写入 plan.md：

| 信号 | 决策 |
|------|------|
| 完全匹配且维护良好 | **采纳**——直接装用，零自研 |
| 部分匹配、底子好 | **扩展**——装用 + 薄封装 |
| 多个弱匹配 | **组合**——2-3 个小包拼装 |
| 无可用方案 | **自研**——调研结论作为 plan 依据 |

反模式：未查重就开写；为一个小功能引入巨型依赖；封装过厚把库的优点封没了。

## 遵守
- 铁律 1（先产出 plan + 验收）
- 拆分模块默认 ≤200 行新增生产代码（铁律 2）
- 更新 memory/project-context.md 待办与迭代状态
